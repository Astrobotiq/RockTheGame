# Proje Denetimi — 2026-09-26

Kapsam: `Assets/` (1453 asset), `ProjectSettings/`, `Packages/manifest.json`, git deposu.
Araç: Unity CLI (`unity command eval`, port 7800, Editor 6000.3.10f1) + statik tarama. **Unity MCP bu oturumda yok.**
Bu denetimde hiçbir dosya, sahne, asset veya ayar değiştirilmedi.

## 1. Özet

Aktif kod (`New-Scripts/`) beklenenden temiz: 0 derleme hatası, 0 konsol hatası, 0 TODO/FIXME, 133 prefab ve 7 sahnede **0 eksik script**, static event abonelikleri dengeli, dosya adı/sınıf adı uyuşmazlığı yok. **Gerçek bir Windows player build'i alındı ve başarılı oldu** (102 sn, 0 `error CS`) — yani projenin build yolu sağlam.

> **Düzeltme (aynı gün):** Bu raporun ilk hâli "player build'i derlenmiyor" diye bir **Kritik** bulgu (C1) içeriyordu. Gerçek build o hipotezi **çürüttü**. Ayrıntı ve nedeni C1 satırında; aşağıdaki kritik üçlü buna göre güncellendi.

Kalan sorunlar iki yerde birikmiş: (a) build'e hiç girmeyen ama repoda duran büyük bir **legacy ada**, (b) pixel art için yanlış **import ayarları**.

**En kritik üç sorun**

1. **E1 — 265 sprite'ın 150'sinde doku sıkıştırması açık**, oyuncu sprite'ları (`Sprites/Candy/*`) dahil. Pixel art'ta renk bozulması ve kenar kirlenmesi yapar.
2. **A1/A2 — Legacy ada.** 25 namespace'siz script + `SampleScene.unity` + 8 eski prefab; hiçbiri build sahnesinde değil, 7'si hiçbir yerden referanssız. İçindeki `Scripts/Input/Input.cs` namespace'siz global bir `@Input` sınıfı tanımlayıp `UnityEngine.Input`'u gölgeliyor. Build raporu bu script'lerin (`door.cs`, `Ring.cs`, `Node.cs`, …) **player build'ine dahil edildiğini** gösteriyor — boyutları ihmal edilebilir (0.1 kb) ama gereksiz.
3. **C2 — `Update` içinde `FindObjectOfType`** (`AirborneCoinShardManager.cs:133`): her karede tüm sahne taranıyor. Yanında **B1** — Active Input Handling `Both` olduğu için Unity konsolu sürekli deprecation uyarısı veriyor, oysa eski Input Manager hiç kullanılmıyor.
